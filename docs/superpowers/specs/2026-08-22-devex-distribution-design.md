# Spec E — DevEx & Distribution

## Goal
Prepare the project for open-source distribution. Scrub all internal branding, establish standard build tooling, automate the release packaging process, and provide user-friendly installation mechanisms including a robust `curl` script and a Homebrew Cask.

## Scope
Items from Codex audit: 7.1, 7.2, 7.3, 7.4, 7.5

## Global Constraints
- Target platform: macOS
- No assumptions about the user's `$HOME` directory path in static files.
- Install script must handle Gatekeeper quarantine stripping correctly.
- Must cleanly uninstall prior versions before installing new ones.

---

## Components

### 1. Brand Scrubbing
The codebase contains legacy references to "solution8" which must be removed to avoid confusion and reflect the open-source nature of the project.

**Targets:**
- Plist filename: `com.solution8.blackhole.dnsd.plist` → `com.blackhole.dnsd.plist`
- Internal plist `Label` string.
- Test mocks (e.g., in `src/dnsd/process_monitor_test.go`) using `com.solution8.*` bundle IDs.
- Any references in code comments, README files, or installer scripts.

### 2. Root Makefile (`Makefile`)
A standard entry point for developers contributing to the project.

**Targets:**
- `build`: Compiles the Go daemon and the xcodebuild Swift project.
- `test`: Runs `go test ./...` and `xcodebuild test`.
- `run-local`: Starts the Go daemon locally (with `sudo` if necessary) for debugging.
- `clean`: Removes `.build/`, `bin/`, and `blackhole-release.zip`.

### 3. Release Packager (`package.sh`)
A bash script to automate the creation of a release artifact.

**Behavior:**
1. Calls `make clean && make build`.
2. Creates a staging directory structure matching the target installation layout.
3. Copies the compiled Go binary, the `.app` bundle, the plist template, and the install script into the staging directory.
4. Zips the staging directory into `blackhole-release.zip`.
5. Computes and outputs the SHA-256 hash of the zip file (required for the Homebrew Cask).

### 4. User-Facing Installer (`install.sh` overhaul)
Upgrades the existing basic deployment script to a robust, publicly usable installer.

**Behavior:**
1. Must not pipe directly to `sudo` from the web; must be downloadable and executable locally.
2. Checks for and stops/unloads any existing Blackhole launch daemons.
3. Removes Gatekeeper quarantine attributes (`xattr -rd com.apple.quarantine`) from the downloaded binary and `.app` bundle before moving them to protected directories.
4. Discovers the executing user's actual `$HOME` directory.
5. Injects the `$HOME` path into `com.blackhole.dnsd.plist` using `sed` to replace the `{{EXCLUSIONS_PATH}}` template variable.
6. Copies the binary to `/usr/local/bin/blackhole-dnsd` (or similar standard location).
7. Copies the `.app` to `/Applications/Blackhole.app`.
8. Copies the injected plist to `/Library/LaunchDaemons/` and loads it via `launchctl`.

### 5. Homebrew Cask (`blackhole.rb`)
A Ruby formula defining how Homebrew installs the application.

**Formula structure:**
- `url`: Points to the GitHub releases page for `blackhole-release.zip`.
- `sha256`: The hash generated by `package.sh`.
- `app`: Installs `Blackhole.app` to `/Applications`.
- `binary`: Links the Go daemon binary.
- `postflight`: Runs necessary setup commands (e.g., loading the launch daemon, which may require `sudo` privileges managed by Homebrew).
- `uninstall`: Explicitly unloads the launch daemon and removes application support files.

## Data Flow (Distribution Pipeline)

```
[Developer runs package.sh]
        ↓
  make build
  Zip artifact created
  SHA-256 computed
        ↓
[Upload to GitHub Releases]
        ↓
[User installs]
  Option A: curl -sSL https://.../install.sh | bash
  Option B: brew install --cask blackhole
```

---

## Testing Requirements
- Unit test (Bash): Run `install.sh` in a mocked environment and verify the plist `{{EXCLUSIONS_PATH}}` is correctly replaced with the current `$HOME`.
- Integration test: Run `make test` and ensure all suites pass.
- Manual verification: Run `package.sh`, inspect the contents of the zip file to ensure no source files or `.git` directories are included.
- Manual verification: Install via the updated `install.sh` and verify Gatekeeper does not block the application launch.
